# ai-usage-rs

Rust CLI tracking account quotas and local capacity across 5 provider routes. Source: `ai-usage-rs/` subfolder.
Hermes routing integration: skill `provider-usage-routing`.

## Commands (binary at ai-usage-rs/target/release/ai-usage)

- `status` / `collect` — current state; collect refreshes ChatGPT, Claude, Z.ai, and local Ollama
- `recommend --json` — machine-readable routing recommendation (call before dispatch)
- `observe <provider> <pct>` — record manual reading (ChatGPT Plus, Ollama Pro)
- `limit-hit <provider>` — record a 429/limit (do this the moment one happens)
- `start-window` — cheap haiku ping that starts Claude's 5h clock NOW
- `alert` — push Telegram alerts on level transitions (dry-run: `AI_USAGE_DRY_RUN=1`)

## Signals

- claude-pro: exact Hermes OAuth quota when the local Dashboard plugin is available;
  otherwise server cache from `~/.claude.json`, then calibrated local JSONL
  (`~/.local/share/ai-usage-optimizer/claude-budget-calibration.json`)
- zai-codeplus: real quota endpoint (needs GLM_API_KEY or ZAI_API_KEY in env);
  correct endpoint is `https://api.z.ai/api/monitor/usage/quota/limit` — NO
  `/coding/paas/v4` prefix; percentage = max across data.limits[] windows
- chatgpt-plus: exact Codex session/weekly allowance via Hermes's authenticated
  `ai-usage-monitor` loopback API (not ordinary ChatGPT conversation usage)
- ollama-pro: manual cloud-plan observations; ollama-local: automatic unmetered
  headroom when localhost:11434 exposes at least one non-`:cloud` model

## Daemon

launchd `com.wesleymatos.ai-usage-collect` runs scripts/collect-cron.sh every 5 min
(sources ~/.hermes/.env for keys, never copies tokens). Telegram push via
`ai-usage alert` (native Rust subcommand) on alert-level transitions only
(ok/warning 90/critical 95). `AI_USAGE_DRY_RUN=1` prints instead of sending.
