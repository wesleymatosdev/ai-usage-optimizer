# ai-usage-rs

Rust CLI tracking usage across 4 AI subscriptions. Source: `ai-usage-rs/` subfolder.
Hermes routing integration: skill `provider-usage-routing`.

## Commands (binary at ai-usage-rs/target/release/ai-usage)

- `status` / `collect` — current state; collect refreshes Claude + Z.ai + credit pools
- `recommend --json` — machine-readable routing recommendation (call before dispatch)
- `route [task-class] [--json]` — session-open routing decision (task-fitness aware)
- `observe <provider> <pct>` — record manual reading (ChatGPT Plus)
- `limit-hit <provider>` — record a 429/limit (do this the moment one happens).
  TRANSIENT since 2026-09-01: writes a TTL'd `rate_events` row (default 15 min),
  never a 100% observation. Verdict is `backoff`, self-clearing.
- `credit record <provider> <dollars-used> [--at-unix TS]` — record a cumulative
  credit-pool reading from the provider dashboard (Ollama Pro: $60/month pool)
- `credit status <provider>` — dollars used/remaining, percent-of-pool, burn rate,
  projected month-end
- `budget check <provider> <estimate>` — REFUSES dispatches that would cross a
  hard ceiling. Token providers take tokens; credit-pool providers (ollama-pro)
  take DOLLARS (e.g. `550` = $5.50 estimated cost). Exit 1 = do not dispatch.
- `budget record <provider> <tokens>` — record actual token spend after a dispatch
- `start-window` — cheap haiku ping that starts Claude's 5h clock NOW
- `alert` — push Telegram alerts on level transitions + burn-projection overruns
  (dry-run: `AI_USAGE_DRY_RUN=1`)

## Signals

- claude-pro: server cache from `~/.claude.json` (cachedUsageUtilization, refreshes
  every few hours — /usage and messages do NOT force it); between refreshes a local
  JSONL token estimate with auto-calibrated budget
  (`~/.local/share/ai-usage-optimizer/claude-budget-calibration.json`); Hermes OAuth
  quota via `collect` when available
- zai-codeplus: real quota endpoint (needs GLM_API_KEY or ZAI_API_KEY in env);
  correct endpoint is `https://api.z.ai/api/monitor/usage/quota/limit` — NO
  `/coding/paas/v4` prefix; percentage = max across data.limits[] windows
- chatgpt-plus: exact Codex quota via Hermes OAuth (`collect`), fallback unavailable
- ollama-pro: CREDIT-POOL model — $60/month balance, dashboard readings via
  `credit record` (cumulative dollars). A 429/session limit is a transient
  `backoff` verdict (TTL 15 min), NEVER a 100% reading; percent = $used/$60.
  Legacy sticky limit-hit rows are auto-migrated on DB open.
- ollama-local: `/api/tags` — unmetered, 0% when reachable with local models

## Verdicts (`recommend --json`)

eligible / local-first / backoff / exhausted / unknown / unavailable.
`backoff` = transient 429 inside the TTL window (retry shortly, balance untouched);
`exhausted` = real plan exhaustion (critical %, or legacy sticky limit-hit on a
non-credit provider).

## Daemon

launchd `com.wesleymatos.ai-usage-collect` runs scripts/collect-cron.sh every 5 min
(sources ~/.hermes/.env for keys, never copies tokens). Telegram push via
`ai-usage alert` (native Rust subcommand) on alert-level transitions only
(ok/warning 90/critical 95), plus a burn-overrun warning when a credit pool's
projection crosses its ceiling. `AI_USAGE_DRY_RUN=1` prints instead of sending.
