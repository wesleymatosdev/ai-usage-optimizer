# ai-usage-rs

Rust CLI tracking account quotas, credit balances, and local capacity across 5 provider routes. Source: `ai-usage-rs/` subfolder.
Hermes routing integration: skill `provider-usage-routing`.

## Provider models (two kinds — do not conflate)

- **percent-of-window** (claude-pro, chatgpt-plus, zai-codeplus, ollama-local):
  a usage percentage of a quota window. Resets clear it.
- **credit_balance** (ollama-pro): a monthly DOLLAR pool ($60 of usage
  credits, verified 2026-09 against ollama.com/pricing), not a rate
  limit. The durable quantity is dollars consumed / remaining; credits reset
  monthly on the subscription start day, do NOT roll over, and when the pool
  hits $0 Ollama draws only from an OPT-IN pay-as-you-go extra-usage balance
  (no auto-reload). There are no 5-hour/weekly session limits on the new
  plans. Transient 429s are a separate TTL'd backoff that NEVER touches the
  balance. Config: `kind: credit_balance`, `monthly_pool_dollars`,
  `reload_monthly_max_dollars` (opt-in extra-usage cap, surfaced only),
  `reset_at` (RFC3339), `rate_limit_ttl_secs` (default 900). Legacy
  `kind: manual` configs are migrated on load.

## Commands (binary at ai-usage-rs/target/release/ai-usage)

- `status` / `collect` — current state; collect refreshes ChatGPT, Claude, Z.ai, and local Ollama
- `recommend --json` — machine-readable routing recommendation (call before dispatch);
  credit providers get verdict `eligible` / `backoff` / `exhausted` from the DOLLAR balance
- `observe <provider> <pct>` — record a manual percent reading
- `credit observe <provider> <used_dollars> [--at-unix TS]` — record dollars consumed (ollama-pro)
- `credit status [provider]` — remaining dollars, burn rate $/h, projected spend at reset
- `limit-hit <provider> [--ttl-secs N] [--at-unix TS]` — record a transient 429
  (backoff only; expires after the TTL, never a 100% observation)
- `budget check <provider> <estimate>` — hard gate: dollars for credit providers, tokens otherwise;
  refuses (exit 1) when recorded + estimate would cross the pool/ceiling
- `budget record <provider> <tokens> [--at-unix TS]` — record actual token spend
- `start-window` — cheap haiku ping that starts Claude's 5h clock NOW
- `alert` — push Telegram alerts on level transitions (dry-run: `AI_USAGE_DRY_RUN=1`)

## Signals

- claude-pro: exact Hermes OAuth quota when the local Dashboard plugin is available;
  otherwise server cache from `~/.claude.json`, then calibrated local JSONL
  (`~/.local/share/ai-usage-optimizer/claude-budget-calibration.json`)
- zai-codeplus: real quota endpoint (needs GLM_API_KEY or ZAI_API_KEY in env);
  correct endpoint is `https://api.z.ai/api/monitor/usage/quota/limit` — NO
  `/coding/paas/v4` prefix; percentage = max across data.limits[] windows
- chatgpt-plus: exact Codex session/weekly allowance via Hermes's authenticated
  `ai-usage-monitor` loopback API (not ordinary ChatGPT conversation usage)
- ollama-pro: `credit observe` with the dashboard's dollar figure; percent is
  derived (dollars / pool). No consumer quota API exists.
- ollama-local: automatic unmetered headroom when localhost:11434 exposes at
  least one non-`:cloud` model

## Daemon

launchd `com.wesleymatos.ai-usage-collect` runs scripts/collect-cron.sh every 5 min
(sources ~/.hermes/.env for keys, never copies tokens). Telegram push via
`ai-usage alert` (native Rust subcommand) on alert-level transitions only
(ok/warning 90/critical 95). `AI_USAGE_DRY_RUN=1` prints instead of sending.
